## Confirmed Phase 7A fixes

- **SQL Injection** previously fell through every match rule to `BENIGN` / confidence `0.0` ("Unknown attack type"). Now resolves to `INITIAL_ACCESS` / `T1190` (Exploit Public-Facing Application).
- **Brute Force -XSS** previously matched the generic `brute force` keyword via substring containment and was misclassified as `CREDENTIAL_ACCESS` / `T1110`. Now resolves to `INITIAL_ACCESS` / `T1190` via an exact canonical match, which is checked before the substring fallback ever runs.
- **Infiltration** is retained at `LATERAL_MOVEMENT` but is now explicitly flagged `heuristic_uncertain` with a documented rationale: the dataset provides one flow-level label regardless of which real kill-chain sub-phase (Initial Access/Execution via the dropped file, vs. Discovery/Lateral Movement via internal probing) produced a given flow.

## Aggregation policy for multiple future-horizon labels

`MitreMapper.from_label_set(labels)` (new in Phase 7A) maps a `;`-joined label set (matching the dataset's own `future_attack_types` column format) to a single `MitrePrediction` by: (1) mapping each label independently via `from_attack_label`, (2) selecting the mapping with the highest `MitreStage` value as the dominant future risk, (3) breaking ties by the alphabetically-first normalized label for full determinism, (4) returning `BENIGN`/confidence `0.0` for no labels. This is a **target/label construction utility only** -- it is not wired into any model input in this phase.
